# Инструкция: настройка вебхука для бота в MAX

Бот получает события (сообщения, нажатия кнопок, старт и остановку бота) одним из двух способов:

| Способ | Когда использовать |
|---|---|
| **Long Polling** (`GET /updates`) | Разработка и отладка. Публичный адрес не нужен, бот сам опрашивает MAX. Скорость и срок хранения событий ограничены. |
| **Webhook** (`POST /subscriptions`) | Продакшен. MAX сам отправляет события на ваш HTTPS-адрес. |

> ⚠️ Использовать оба способа одновременно нельзя. Пока у бота есть webhook-подписка, polling не работает, и наоборот.

---

## Подготовка

Перед началом убедитесь, что у вас есть:
* бот в MAX и его токен (см. шаг 1);
* публичный домен с HTTPS и доверенным сертификатом;
* сервер, который принимает HTTPS POST-запросы на порту 443 и отвечает не дольше чем за 30 секунд.

---

## Шаг 1. Создание бота и получение токена

1. Войдите на [платформу MAX для партнёров](https://business.max.ru/self). Нужен верифицированный профиль организации, ИП или самозанятого.
2. В разделе **«Чат-боты»** создайте бота, заполните обязательные поля и отправьте его на модерацию.
3. Токен находится в **«Чат-боты» → ⋮ → «Настройки»**. Если бот создан в мини-приложении «MAX для бизнеса», токен можно получить там же или командой **«Получить токен»** в боте «MAX для бизнеса».
4. Сохраните токен в `.env` (`MAX_BOT_TOKEN`). Это секрет: **не передавайте его третьим лицам и не коммитьте в репозиторий.** За нарушение правил платформы токен могут отозвать.

---

## Шаг 2. Подготовка endpoint

**Требования MAX к адресу вебхука:**
* только **HTTPS**, порт **443**. Порт в URL не указывается: `https://bot.example.com/max/webhook`;
* сертификат выдан **доверенным центром сертификации или Минцифры**. Самоподписанные сертификаты не поддерживаются, вебхуки по HTTP тоже;
* домен в URL совпадает с CN или SAN сертификата;
* сервер отдаёт **полную цепочку** сертификатов, включая промежуточные;
* на каждый запрос нужно ответить **HTTP 200 не позже чем через 30 секунд**. Любой другой код или превышение таймаута считается ошибкой доставки.

**Что происходит при ошибках доставки:**
* MAX повторяет запрос до 10 раз с растущим интервалом: 60 с, 150 с, 375 с и т. д.;
* если за **8 часов** не было ни одного успешного ответа, MAX **автоматически удаляет подписку**. После восстановления сервера её нужно зарегистрировать заново: у нашего бота это происходит при перезапуске.

**Типовая схема для нашего бота:** на сервере работает Node.js-процесс бота, перед ним стоит обратный прокси с TLS. Удобнее всего [Caddy](https://caddyserver.com/): он сам получает и продлевает сертификат Let's Encrypt.

```
# /etc/caddy/Caddyfile
bot.example.com {
    reverse_proxy /max/webhook*     localhost:3001   # события MAX
    reverse_proxy /payments/webhook localhost:3000   # уведомления эквайера об оплате
}
```

DNS-запись `bot.example.com` должна указывать на сервер, порты 80 и 443 должны быть открыты.

## Шаг 3. Регистрация подписки на события

### Вариант А: наш бот регистрирует подписку сам (рекомендуется)

Задайте в `.env` на сервере:

```ini
MAX_MODE=webhook
MAX_WEBHOOK_DOMAIN=https://bot.example.com
MAX_WEBHOOK_PORT=3001
MAX_WEBHOOK_PATH=/max/webhook
MAX_WEBHOOK_SECRET=длинная_случайная_строка   # 5–256 символов: латиница, цифры, «_», «-»
```

При запуске (`npm run bot`) бот:
1. поднимает HTTP-сервер на `MAX_WEBHOOK_PORT`;
2. регистрирует подписку `https://bot.example.com/max/webhook` с нужными типами событий (`bot_started`, `bot_stopped`, `message_created`, `message_callback`) и секретом;
3. **удаляет все остальные webhook-подписки бота**: библиотека MAX оставляет только активную;
4. отвечает MAX `200 OK` сразу после приёма события и обрабатывает его уже после ответа, поэтому 30-секундный лимит не мешает долгим операциям;
5. отклоняет запросы с неверным заголовком `X-Max-Bot-Api-Secret`.

### Вариант Б: вручную через API

Отправьте POST-запрос на `https://platform-api2.max.ru/subscriptions`.

**Заголовки**

| Заголовок | Значение |
| --- | --- |
| `Authorization` | `<ваш_токен>` (без префикса `Bearer`; передача токена в query-параметре больше не поддерживается) |
| `Content-Type` | `application/json` |

**Тело запроса (JSON)**

```json
{
  "url": "https://bot.example.com/max/webhook",
  "update_types": ["bot_started", "bot_stopped", "message_created", "message_callback"],
  "secret": "YOUR_WEBHOOK_SECRET"
}
```

| Поле | Обязательное | Описание |
|---|---|---|
| `url` | да | HTTPS-адрес endpoint |
| `update_types` | нет | Типы событий. Если не указать, придут все. Список типов — в описании объекта [Update](https://dev.max.ru/docs-api/objects/Update) |
| `secret` | нет, но настоятельно рекомендуется | 5–256 символов `[a-zA-Z0-9_-]`. Приходит в заголовке `X-Max-Bot-Api-Secret` каждого запроса, сервер должен его проверять |

**Пример (bash):**
```bash
curl -X POST "https://platform-api2.max.ru/subscriptions" \
  -H "Authorization: $MAX_BOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://bot.example.com/max/webhook","update_types":["bot_started","bot_stopped","message_created","message_callback"],"secret":"YOUR_WEBHOOK_SECRET"}'
```

Ответ: `{"success": true}`. При ошибке приходит `{"success": false, "message": "…"}`. Обратите внимание, что HTTP-статус и в этом случае бывает `200`.

> curl и PowerShell не знают сертификатов Минцифры, которыми подписан `platform-api2.max.ru`. Для Windows проще использовать команды проекта (ниже): они подключают сертификаты из `ca/`.

## Проверка и управление подписками

Команды проекта (на Windows в PowerShell используйте `npm.cmd`):

```bash
npm run check:max                 # связь с API, токен и есть ли webhook
npm run webhooks                  # список подписок
npm run webhooks -- delete <url>  # удалить подписку
npm run webhooks -- delete-all    # удалить все (нужно перед запуском в режиме polling)
```

Те же операции через API:
```bash
curl "https://platform-api2.max.ru/subscriptions" -H "Authorization: $MAX_BOT_TOKEN"
curl -X DELETE "https://platform-api2.max.ru/subscriptions?url=https://bot.example.com/max/webhook" \
  -H "Authorization: $MAX_BOT_TOKEN"
```

## Переключение между webhook и polling

* **Webhook → polling** (локальная отладка): при запуске `npm run dev` бот увидит подписку и остановится с подсказкой. Удалите её командой `npm run webhooks -- delete-all` или задайте `MAX_DROP_WEBHOOKS=1`. Пока подписки нет, продакшен-сервер событий не получает.
* **Polling → webhook**: запустите бота на сервере с `MAX_MODE=webhook`, он зарегистрирует подписку сам.
* Чтобы не мешать рабочему боту, для разработки удобнее завести **отдельного тестового бота** со своим токеном.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| События не приходят, подписка есть | Проверьте, что `https://<домен>/max/webhook` открывается извне, сертификат доверенный и отдаётся полная цепочка, а прокси ведёт на правильный порт |
| Подписка пропала сама | Сервер был недоступен больше 8 часов, и MAX её удалил. Перезапустите бота, он зарегистрирует подписку снова |
| Бот не стартует: «настроен webhook» | Запуск в режиме polling при существующей подписке. См. раздел «Переключение» |
| Ответ 401 | Неверный токен или он передан не в заголовке `Authorization` |
| `unable to get local issuer certificate` | Node.js не знает сертификатов Минцифры. Проверьте папку `ca/` (см. README) |
