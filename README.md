# mxbt-AutoScoring

Бот для мессенджера MAX: страховка от поломки двигателя и коробки передач.
Пользователь указывает VIN или госномер, подтверждает данные автомобиля и пробег. Бот проводит асинхронный скоринг с «живым» статусом в чате и предлагает цену за год и помесячно, после чего ведёт на оплату.

Все внешние сервисы, кроме самого MAX, пока заменены **mock-сервером**: госномер → VIN, VIN → данные авто, AI + поиск, прайсинг и эквайер.

## Быстрый старт

Нужны Node.js 22.19+ и токен бота MAX.

```bash
npm install
cp .env.example .env      # впишите MAX_BOT_TOKEN
npm run check:max         # проверка связи с API MAX: сертификаты и токен
npm run dev               # mock-сервисы и бот в одном процессе, long polling
```

На Windows в PowerShell используйте `npm.cmd` вместо `npm`, если выполнение скриптов отключено.

### Webhook или polling

Бот получает события от MAX одним из двух способов: через webhook или через long polling. Использовать оба одновременно нельзя. При запуске в режиме polling (`npm run dev`) все webhook-подписки бота удаляются. Если подписки есть, бот по умолчанию не стартует и показывает их список, чтобы случайно не отключить другой сервис.

```bash
npm run webhooks                  # показать подписки
npm run webhooks -- delete <url>  # удалить одну
npm run webhooks -- delete-all    # удалить все
```

Чтобы удалять подписки без вопросов, задайте `MAX_DROP_WEBHOOKS=1`. Webhook можно вернуть позже: запустите бота с `MAX_MODE=webhook` или зарегистрируйте подписку заново там, где она была настроена.

### Сертификаты Минцифры

API MAX (`platform-api2.max.ru`) подписан сертификатом **Russian Trusted Root CA**, а Node.js ему по умолчанию не доверяет: запросы падают с ошибкой `unable to get local issuer certificate`. Корневой и промежуточные сертификаты лежат в папке `ca/` и подключаются при старте автоматически (`src/tls-ca.ts`). Устанавливать их в систему или задавать `NODE_EXTRA_CA_CERTS` не нужно.

- Свежие версии сертификатов публикуются на gosuslugi.ru/crt. Принимаются форматы PEM и DER с расширениями `.cer`, `.crt` и `.pem`.
- Просроченные сертификаты пропускаются. За 60 дней до окончания срока в лог выводится предупреждение. `Russian Trusted Sub CA` (2022) действует до марта 2027 года.
- Чтобы указать другой каталог, задайте `CA_DIR`.

Затем откройте бота в MAX и нажмите «Начать» или отправьте `/start`.

Компоненты можно запускать и по отдельности: `npm run mocks` в одном терминале, `npm run bot` в другом.

Проверки:

```bash
npm test                  # unit-тесты и сквозные сценарии без MAX
npm run typecheck
```

## Тестовые сценарии

| Ввод | Что произойдёт |
|---|---|
| VIN `JTNB23HK103012345` | Toyota Camry 2019, АКПП. Обычный путь |
| VIN `LVTDB21B4ND123456` или госномер `Е444КХ777` | Chery Tiggo 7 Pro, вариатор и турбо. Обогащение находит риски, цена выше |
| Госномер `А111АА77` | Найден один VIN (VW Polo). VIN в карточке замаскирован |
| Госномер `В222ВВ99` | Найдено несколько VIN, пользователь выбирает свой |
| Госномер `С333СС50` | Номер не найден, бот просит VIN |
| Госномер `М555ММ77` или любой VIN на `…00000` | VIN есть, но декодер его не знает, марка, модель и год вводятся вручную |
| Любой другой корректный госномер | Детерминированно генерируется VIN и модель из каталога |
| VIN на `…88888`, например `XW8ZZZ61ZJG088888` | Долгий скоринг, 90 с. Можно закрыть чат и дождаться push с предложением |
| VIN на `…77777` | Отказ в страховании |
| VIN на `…99999` | Техническая ошибка скоринга, бот предлагает повторить |

**Оплата.** Тестовая страница виджета живёт на mock-сервере. По умолчанию её адрес `http://localhost:4000`, а MAX не принимает такие ссылки в кнопках. Поэтому в dev-режиме вместо кнопки «💳 Перейти к оплате» приходит текстовая ссылка и кнопка «📋 Скопировать ссылку на оплату». Открыть её можно только на том же компьютере.

Чтобы была настоящая кнопка и страница открывалась с телефона, опубликуйте порт 4000 через HTTPS-туннель и укажите адрес туннеля в `MOCKS_PUBLIC_URL`:

```powershell
winget install --id Cloudflare.cloudflared      # один раз
cloudflared tunnel --url http://localhost:4000   # покажет адрес вида https://xxxx.trycloudflare.com
```

В `.env` впишите `MOCKS_PUBLIC_URL=https://xxxx.trycloudflare.com` и перезапустите `npm run dev`. Адрес временного туннеля меняется при каждом запуске cloudflared. Подойдёт и любой другой HTTPS-туннель, например tuna.am. В продакшене у эквайера (CloudPayments) публичный HTTPS-адрес, так что там всегда будет кнопка.

Без страницы можно обойтись: в чате есть кнопки **🧪 Оплата успешна / 🧪 Отказ банка**, они отключаются через `PAYMENT_SHORTCUTS=0`. В обоих случаях результат приходит в бот так же, как от настоящего эквайера: через подписанный webhook на `POST /payments/webhook`.


## Установка на сервер

Установка на Debian 12 (nginx с Let's Encrypt, systemd, режим webhook) выполняется одним скриптом `deploy/install.sh`. Краткая памятка лежит в [docs/install-quickstart.md](docs/install-quickstart.md), подробности в [docs/deploy.md](docs/deploy.md). Как работает webhook MAX, описано в [docs/max-web-hook.md](docs/max-web-hook.md).

## Устройство

```
src/
  main.ts                 запуск: MAX (polling/webhook) + HTTP-сервер для webhook оплаты
  config.ts               переменные окружения
  tls-ca.ts               подключение сертификатов Минцифры из ca/
  messenger/
    types.ts              порт мессенджера (события, кнопки, отправка и правка)
    max.ts                адаптер MAX на @maxhub/max-bot-api
  bot/
    insurance-bot.ts      клиентский путь (FSM), фоновый скоринг, «живой» прогресс, оплата
    texts.ts              все тексты бота
    session.ts            состояние диалога (пока в памяти, интерфейс под Redis/Postgres)
    contact.ts            проверка телефона из request_contact (HMAC-SHA256 с токеном бота)
  domain/
    identifiers.ts        VIN и госномер: нормализация, проверка, маскирование
    vehicle.ts            профиль авто как набор утверждений с источником (client / vin_service / …)
  services/
    ports.ts              контракты внешних сервисов
    http.ts               HTTP-клиенты к ним и mock-адаптер эквайера
  http.ts                 POST /payments/webhook, GET /health
ca/                       корневой и промежуточные сертификаты Минцифры
scripts/
  dev.ts                  mock-сервисы и бот в одном процессе
  check-max.ts            проверка связи с API MAX
mocks/
  server.ts               mock-сервер всех внешних сервисов
  fixtures.ts             тестовые автомобили и госномера
tests/                    unit-тесты и сквозные сценарии с мессенджером-двойником
deploy/                   install.sh, update.sh, systemd-юниты, конфиг nginx
docs/customer-journey.md  клиентский путь и принятые решения
docs/install-quickstart.md  кратко: как установить на сервер
docs/deploy.md            установка на сервер подробно
docs/max-web-hook.md      webhook MAX
```

**Как подключить реальный сервис.** Нужно реализовать интерфейс из `src/services/ports.ts`, например `PlateToVinService` или `PaymentProvider`, и подставить его в `src/main.ts`. Логику бота менять не придётся. Чтобы сменить эквайера, достаточно написать новый адаптер `PaymentProvider` с методами `createPayment` и `parseWebhook` (проверка подписи).
